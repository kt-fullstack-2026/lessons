1장. Git과 GitHub로 협업하기

GitHub와 원격 저장소 — push · clone · fetch · pull

준비시간1시간 30분개념 지도로컬 저장소 ↔ 원격 저장소

한 줄 요약

내 PC의 저장소(로컬)를 GitHub의 저장소(원격)와 연결해 올리고(push) 받습니다(pull). 팀원이 같은 원격 저장소를 쓰면 협업이 됩니다.

1. 네 가지 명령

명령 방향 하는 일
git clone 주소 원격 → 내 PC 원격 저장소를 기록째 처음 받는다 (5절에서 자세히)
git push 내 PC → 원격 내 커밋을 올린다
git fetch 원격 → 내 PC 원격의 새 커밋을 받기만 한다. 내 파일은 바뀌지 않는다
git pull 원격 → 내 PC 받아서 내 브랜치에 합친다

origin은 원격 저장소의 별명입니다. 보통 GitHub 주소를 가리킵니다.

pull = fetch(받기) + merge(합치기). 받기만 하고 싶으면 fetch를 씁니다.

2. 따라하기 — 내 저장소를 GitHub에 올리기

(1) GitHub에 빈 저장소 만들기

GitHub 오른쪽 위 + → New repository에서 이름을 my-first-repo로 하고, README 추가는 체크하지 않고 만듭니다. 이미 내 PC에 README가 있기 때문입니다.

(2) 연결하고 올리기

GitHub 화면에 나오는 주소를 복사해 씁니다.

$ git remote add origin https://github.com/내아이디/my-first-repo.git
$ git remote -v
$ git push -u origin main

실행 결과 (진행 상황을 알리는 Enumerating objects... 같은 줄은 생략)

origin  https://github.com/내아이디/my-first-repo.git (fetch)
origin  https://github.com/내아이디/my-first-repo.git (push)
To https://github.com/내아이디/my-first-repo.git
 * [new branch]      main -> main
branch 'main' set up to track 'origin/main'.

-u는 "앞으로 이 브랜치는 origin/main과 짝"이라고 정해 두는 옵션입니다. 한 번 하면 다음부터는 git push만 쳐도 됩니다.

(3) 처음 push할 때 로그인 창

처음 push하면 Git Credential Manager 창이 뜹니다. Sign in with your browser를 눌러 GitHub에 로그인합니다. 한 번 로그인하면 윈도우가 기억합니다.

GitHub는 2021년 8월 13일부터 Git 작업에 계정 비밀번호를 받지 않습니다. 터미널에 비밀번호를 쳐도 실패합니다. 브라우저 로그인이나 토큰을 씁니다. (GitHub Changelog)

3. 팀원이 올린 것 받기

팀원이 같은 저장소를 받아(clone) 한 줄을 추가해 올렸다고 합시다. 나는 먼저 확인만 합니다.

$ git fetch
$ git status

실행 결과

On branch main
Your branch is behind 'origin/main' by 1 commit, and can be fast-forwarded.
  (use "git pull" to update your local branch)

nothing to commit, working tree clean

"원격보다 1커밋 뒤에 있다"는 뜻입니다. 받아서 합칩니다.

$ git pull

Updating 73ed024..2fa25f9
Fast-forward
 README.md | 1 +
 1 file changed, 1 insertion(+)

4. push가 거절될 때

팀원이 먼저 올린 상태에서 내가 push하면 거절됩니다.

실행 결과

To https://github.com/내아이디/my-first-repo.git
 ! [rejected]        main -> main (fetch first)
error: failed to push some refs to 'https://github.com/내아이디/my-first-repo.git'
hint: Updates were rejected because the remote contains work that you do not
hint: have locally. This is usually caused by another repository pushing to
hint: the same ref. If you want to integrate the remote changes, use
hint: 'git pull' before pushing again.
hint: See the 'Note about fast-forwards' in 'git push --help' for details.

"원격에 내가 없는 커밋이 있으니, 먼저 pull로 받아서 합친 다음 다시 push하라"는 뜻입니다. 고장이 아닙니다. git pull → (충돌이 나면 해결) → git push 순서로 합니다.

5. git clone 주소와 git clone 주소 .의 차이

clone은 원격 저장소를 내 PC로 복사합니다. 주소 뒤에 .을 붙이느냐에 따라 파일이 들어가는 위치가 달라집니다. .은 "지금 이 폴더"라는 뜻입니다(2절).

명령 파일이 들어가는 곳 조건
git clone 주소 현재 위치 아래에 저장소 이름으로 새 폴더를 만들고 그 안에 없음
git clone 주소 . 지금 이 폴더에 바로 지금 폴더가 비어 있어야 함
git clone 주소 폴더이름 현재 위치 아래에 지정한 이름의 새 폴더를 만들고 그 안에 없음 
$ cd /d/workspace
$ git clone https://github.com/내아이디/my-first-repo.git

실행 결과 (앞부분)

Cloning into 'my-first-repo'...

/d/workspace/my-first-repo 폴더가 새로 생깁니다. 다음 명령을 치기 전에 cd my-first-repo로 들어가야 합니다.

$ mkdir /d/workspace/team-project
$ cd /d/workspace/team-project
$ git clone https://github.com/내아이디/my-first-repo.git .

실행 결과 (앞부분)

Cloning into '.'...

새 폴더 없이 team-project 폴더에 바로 파일과 .git이 들어옵니다. 폴더 안에 파일이 하나라도 있으면 아래처럼 거절됩니다.

fatal: destination path '.' already exists and is not an empty directory.

처음에는 git clone 주소(점 없이)를 씁니다. 폴더가 새로 생기므로 다른 파일과 섞이지 않습니다. .은 IntelliJ 등으로 빈 폴더를 미리 만들어 둔 경우에만 씁니다. clone 뒤에는 cd로 그 폴더에 들어갔는지 pwd로 확인합니다.

6. 내 PC의 Git 설정과 로그인 정보 지우기

공용 PC를 쓸 때, 다른 GitHub 계정으로 바꿀 때, 과정이 끝나 PC를 정리할 때 씁니다. 개인 PC를 계속 쓴다면 할 필요가 없습니다.

지울 것 명령 또는 방법 영향 범위
사용자 이름·이메일 git config --global --unset 이 PC의 모든 저장소
원격 연결(origin) git remote rm origin 명령을 친 저장소 하나
GitHub 로그인 정보 Windows 자격 증명 관리자 이 PC의 GitHub 로그인

(1) 사용자 이름과 이메일 지우기

$ git config --global --unset user.name
$ git config --global --unset user.email
$ git config --global --list

--list 결과에 user.name, user.email이 없으면 지워진 것입니다. 이미 지운 값을 다시 지우면 아무 메시지 없이 끝납니다.

(2) 원격 저장소 연결 끊기

저장소 폴더 안에서 칩니다.

$ git remote -v
$ git remote rm origin
$ git remote -v

마지막 git remote -v에 아무것도 나오지 않으면 연결이 끊긴 것입니다. 내 PC의 파일과 커밋, GitHub의 저장소는 그대로 남습니다. rm은 remove의 줄임말이라 git remote remove origin과 같습니다.

(3) GitHub 로그인 정보(자격 증명) 지우기

2-(3)에서 브라우저로 로그인한 정보는 Windows의 자격 증명 관리자에 저장되어 있습니다.

  1. 시작 메뉴에서 자격 증명 관리자를 검색해 엽니다.
  2. Windows 자격 증명을 누릅니다.
  3. 일반 자격 증명 목록에서 git:https://github.com을 펼쳐 제거를 누릅니다.

명령으로 지울 수도 있습니다.

$ printf "protocol=https\nhost=github.com\n\n" | git credential reject

다음에 push하면 로그인 창이 다시 뜹니다. 다른 계정으로 로그인하면 됩니다.

명령을 복사해 붙여 넣을 때 보이지 않는 글자를 조심합니다. 웹 문서나 메신저에서 복사한 명령에는 눈에 안 보이는 글자가 섞일 수 있고, 그러면 error: invalid key: user.email, error: No such remote: 'origin'처럼 이름이 맞는데도 오류가 납니다. 이럴 때는 명령을 직접 다시 칩니다.

핵심 정리

  • clone은 처음 한 번, push는 올리기, fetch는 확인만, pull은 받아서 합치기.
  • 처음 push는 git push -u origin main, 로그인은 브라우저로.
  • push가 거절되면 pull 먼저.
  • 처음에는 git clone 주소(새 폴더), 빈 폴더가 있을 때만 git clone 주소 ..
  • PC를 정리할 때는 사용자 정보 · 원격 연결 · 자격 증명을 지운다.
