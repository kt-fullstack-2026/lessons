1장. Git과 GitHub로 협업하기

따라하기 — 첫 저장소와 첫 커밋

준비시간1시간 30분개념 지도작업 폴더 · 스테이징 · 로컬 저장소

목표

Git Bash에서 저장소를 만들고 커밋을 두 번 찍습니다. 매 단계마다 git status로 파일이 어느 영역에 있는지 확인합니다.

실행 결과의 커밋 번호(예: 932e50d)와 폴더 경로는 사람마다 다릅니다. 나머지 문구가 같으면 성공입니다.

1. 저장소 만들기 — git init

$ mkdir my-first-repo
$ cd my-first-repo
$ git init

실행 결과

Initialized empty Git repository in D:/workspace/my-first-repo/.git/

.git이라는 숨김 폴더가 생겼습니다. 이 폴더가 사진첩(로컬 저장소)입니다. 지우면 모든 기록이 사라집니다.

$ git status

On branch main

No commits yet

nothing to commit (create/copy files and use "git add" to track)

2. 파일 만들고 상태 보기

$ printf '# 자기소개\n\n이름: 나학생\n' > README.md
$ git status

실행 결과

On branch main

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
    README.md

nothing added to commit but untracked files present (use "git add" to track)

Untracked — Git이 아직 모르는 새 파일입니다.

3. 고르고(add) 찍기(commit)

$ git add README.md
$ git status

On branch main

No commits yet

Changes to be committed:
  (use "git rm --cached <file>..." to unstage)
    new file:   README.md

이제 상자에 담겼습니다. 사진을 찍습니다.

$ git commit -m "docs: 자기소개 README 추가"

실행 결과

[main (root-commit) 932e50d] docs: 자기소개 README 추가
 1 file changed, 3 insertions(+)
 create mode 100644 README.md

4. 무엇이 바뀌었나 — git diff

README에 한 줄을 추가합니다.

$ printf '목표: 풀스택 개발자\n' >> README.md
$ git diff

실행 결과

diff --git a/README.md b/README.md
index 77003f4..7ab7975 100644
--- a/README.md
+++ b/README.md
@@ -1,3 +1,4 @@
 # 자기소개

 이름: 나학생
+목표: 풀스택 개발자

+로 시작하는 줄이 추가된 줄, -로 시작하면 지운 줄입니다. 커밋 전에 git diff로 한 번 보는 습관을 들입니다.

$ git add README.md
$ git commit -m "docs: 목표 추가"

5. 사진첩 보기 — git log

$ git log --oneline

실행 결과

ef983ad (HEAD -> main) docs: 목표 추가
932e50d docs: 자기소개 README 추가

맨 위가 가장 최근 커밋입니다. 괄호 안의 HEAD -> main은 "지금 main 브랜치에 있고, main이 이 커밋을 가리킨다"는 뜻입니다.

6. 저장 안 한 수정 버리기 — git restore

실수로 README를 망가뜨렸다고 합시다.

$ echo "실수로 지운 내용" > README.md
$ git status --short

 M README.md

마지막 사진의 상태로 되돌립니다.

$ git restore README.md
$ cat README.md

# 자기소개

이름: 나학생
목표: 풀스택 개발자

git restore 파일은 커밋하지 않은 수정을 버립니다. 버린 수정은 되찾을 수 없으므로, 치기 전에 git status로 무엇을 버리는지 확인합니다.

7. 파일 지우기 — 탐색기에서 지우고 커밋

Git에서 파일을 지우는 명령(git rm)이 따로 있지만, Git이 익숙해지기 전에는 쓰지 않습니다. 평소처럼 탐색기나 VS Code에서 파일을 지운 뒤, 그 상태를 커밋합니다.

연습용 파일을 하나 만들어 커밋합니다.

$ printf '공부할 것: Git\n' > memo.txt
$ git add memo.txt
$ git commit -m "docs: 메모 추가"

이제 탐색기에서 memo.txt를 지우고 상태를 봅니다.

$ git status

실행 결과

On branch main
Changes not staged for commit:
  (use "git add/rm <file>..." to update what will be committed)
  (use "git restore <file>..." to discard changes in working directory)
    deleted:    memo.txt

no changes added to commit (use "git add" and/or "git commit -a")

Git은 "파일이 지워졌다"는 것도 변경으로 봅니다. 고친 파일과 똑같이 add → commit 합니다.

$ git add .
$ git commit -m "chore: 메모 삭제"

실행 결과

[main 310a2ea] chore: 메모 삭제
 1 file changed, 1 deletion(-)
 delete mode 100644 memo.txt

파일과 폴더는 탐색기에서 지우고, git add . → git commit으로 기록합니다. 커밋하기 전이라면 git restore memo.txt로 되살릴 수 있습니다. 커밋한 뒤에도 이전 커밋에는 파일이 남아 있습니다.

핵심 정리

  • git init → 파일 수정 → git add → git commit -m "메시지"
  • 커밋 전에는 git status와 git diff로 확인한다.
  • git log --oneline으로 사진첩을 본다.
  • git restore는 커밋하지 않은 수정을 버린다.
  • 파일은 탐색기에서 지우고 git add . → git commit으로 기록한다.
