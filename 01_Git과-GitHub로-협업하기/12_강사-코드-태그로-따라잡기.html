1장. Git과 GitHub로 협업하기

강사 코드 태그로 따라잡기 — clone · tag · switch --detach

준비시간40분개념 지도원격 저장소 → 내 PC

한 줄 요약

이 수업은 녹화가 없습니다. 수업 중에 놓치면 강사 저장소의 태그로 그 시점의 코드를 바로 받아 이어서 따라갑니다. 태그는 "움직이지 않는 이름표"입니다.

1. 태그는 고정된 이름표

태그란? 특정 커밋에 붙이는 고정된 이름입니다. 6절의 브랜치는 새 커밋을 만들면 따라 옮겨 가지만, 태그는 한 번 붙이면 옮겨 가지 않습니다.

브랜치 태그
커밋하면 따라 움직인다 그대로 있다
쓰는 곳 작업 수업 단계 표시, 배포 버전(v1.0.0)

강사는 수업의 단계마다 태그를 붙입니다. 이름 규칙은 ch장번호-step단계-내용입니다.

ch10-step1-entity     10장 1단계: Entity까지 완성
ch10-step2-service    10장 2단계: Service까지 완성
ch10-step3-controller 10장 3단계: Controller까지 완성

각 절 위쪽의 코드 태그 표시가 바로 이 이름입니다.

2. 따라하기 — 강사 저장소 받기 (처음 한 번)

강사 코드는 조직의 lecture-code 저장소에 있습니다. 내 작업 폴더와 섞이지 않도록 따로 받습니다.

$ cd /d/workspace
$ git clone https://github.com/<조직이름>/lecture-code.git
$ cd lecture-code

<조직이름>은 강사가 알려 준 GitHub 조직 이름으로 바꿉니다.

실행 결과 (앞부분)

Cloning into 'lecture-code'...

clone은 저장소 전체(모든 기록과 태그)를 내 PC로 복사합니다. init + remote add + pull을 한 번에 하는 것과 같습니다.

3. 따라하기 — 놓친 단계로 이동

3-1. 새 태그 받기

수업 중에 강사가 새 태그를 올렸다면 먼저 받아 옵니다.

$ git fetch --tags
$ git tag

실행 결과 (예시)

From https://github.com/<조직이름>/lecture-code
 * [new tag]         ch10-step2-service -> ch10-step2-service
ch10-step1-entity
ch10-step2-service

git tag는 받은 태그 목록을 보여 줍니다.

3-2. 그 태그 시점으로 이동

$ git switch --detach ch10-step2-service

실행 결과 (예시)

HEAD is now at 85cdc97 feat: 게시글 Service 추가

이제 폴더의 파일이 그 단계가 끝난 시점의 코드로 바뀌었습니다. IntelliJ에서 이 폴더를 열고 실행해 보면 됩니다.

--detach는 "브랜치 없이 사진만 펼쳐 보기"입니다. HEAD가 브랜치가 아니라 커밋을 직접 가리킵니다. 이 상태에서 커밋하면 이름표가 없어서 나중에 찾기 어렵습니다. 보기만 하고, 고치지 않습니다.

3-3. 원래대로 돌아오기

$ git switch main

실행 결과 (예시)

Previous HEAD position was 85cdc97 feat: 게시글 Service 추가
Switched to branch 'main'

커밋 번호(85cdc97)와 메시지는 저장소마다 다릅니다. 모양만 확인합니다.

4. 놓쳤을 때 실제 순서

따라잡기 4단계

  1. "놓쳤다"를 알린다.
  2. lecture-code 폴더에서 git fetch --tags
  3. git switch --detach 그-절의-코드-태그
  4. 그 코드를 보며 내 작업 폴더에서 이어서 친다. (복사보다 비교하며 고치기를 권장)

강사 코드를 내 폴더로 통째로 복사하면 어디를 놓쳤는지 모른 채 넘어갑니다. 두 창을 나란히 놓고 차이를 찾아 고치는 것이 가장 빨리 따라잡는 방법입니다.

단계 사이에 어떤 파일이 바뀌었는지는 직접 확인할 수 있습니다.

$ git diff ch10-step1-entity ch10-step2-service --stat
