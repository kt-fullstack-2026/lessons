1장. Git과 GitHub로 협업하기

설치와 첫 설정 — Git Bash와 GitHub 계정

준비시간사전학습개념 지도내 PC

목표

내 PC에 Git을 설치하고, Git Bash에서 처음 한 번만 하는 설정을 끝냅니다. 그리고 GitHub 계정을 만듭니다.

1. Git for Windows 설치

  1. git-scm.com에서 Windows용 Git을 내려받아 설치합니다.
  2. 설치 화면은 대부분 기본값 그대로 둡니다. 아래 두 화면만 확인합니다.
설치 화면 고를 것 이유
Choosing the default editor VS Code가 설치되어 있으면 VS Code, 아니면 Notepad 기본값 Vim은 입문자가 빠져나오기 어렵습니다
Adjusting the name of the initial branch Override … main GitHub의 기본 브랜치 이름과 맞춥니다
  1. 설치가 끝나면 시작 메뉴에서 Git Bash를 엽니다. 검은 창이 뜨면 성공입니다.

Git Bash는 윈도우에서 리눅스식 명령(ls, cd, pwd)을 쓸 수 있게 해 주는 터미널입니다. 이 과정의 모든 Git 실습은 Git Bash에서 합니다.

2. 처음 한 번만 하는 설정

Git Bash에 아래를 한 줄씩 입력합니다. 이름과 이메일은 본인 것으로 바꿉니다. 이메일은 GitHub 가입에 쓸 이메일과 같게 합니다.

$ git config --global user.name "나학생"
$ git config --global user.email "student@example.com"
$ git config --global init.defaultBranch main
$ git config --global pull.rebase false
$ git config --global core.quotepath false
설정 뜻
user.name, user.email 커밋에 찍히는 "누가 찍었나" 정보
init.defaultBranch main 새 저장소의 첫 브랜치 이름을 main으로
pull.rebase false pull할 때 합치는 방식을 merge로 정해 둔다 (아래 상자에서 이유를 봅니다)
core.quotepath false 한글 파일 이름이 \354\236\220처럼 깨져 보이지 않게

설정이 잘 들어갔는지 확인합니다.

$ git config --global --list

실행 결과

user.name=나학생
user.email=student@example.com
init.defaultbranch=main
pull.rebase=false
core.quotepath=false

pull.rebase false를 빼먹으면, 나중에 팀원과 동시에 작업한 뒤 git pull을 할 때 "You have divergent branches and need to specify how to reconcile them."라는 안내와 함께 멈춥니다. 미리 정해 두면 이 문제를 피할 수 있습니다.

3. GitHub 계정 만들기

  1. github.com에서 가입합니다. 아이디는 포트폴리오에 그대로 쓰일 이름으로 정합니다.
  2. 2단계 인증(2FA)을 켭니다. GitHub가 강력히 권장하고, 과정 Organization에서 요구할 수 있습니다. (GitHub Docs)

4. 사전학습 제출물

아래 두 화면을 캡처해 제출하면 Git 과제 완료입니다.

  1. git --version 결과
  2. git config --global --list 결과

핵심 정리

  • 실습은 Git Bash에서 한다.
  • 설정은 처음 한 번, --global로 한다.
  • 이메일은 GitHub 계정과 같게, 기본 브랜치는 main, pull.rebase false를 넣는다.
