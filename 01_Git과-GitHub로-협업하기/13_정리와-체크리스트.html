1장. Git과 GitHub로 협업하기

정리와 체크리스트

준비시간20분개념 지도전체 흐름

1장에서 배운 것

  • Git과 GitHub — Git은 내 PC의 기록 도구, GitHub는 그 기록을 올려 두고 함께 쓰는 인터넷 서비스다.
  • 커밋 — 특정 시점의 프로젝트 파일 상태를 저장한 기록. 작업 폴더 → 스테이징(add) → 저장소(commit) 세 영역을 지난다.
  • 브랜치 — 커밋을 가리키는 이름. 새 커밋을 만들면 따라 옮겨 간다. main은 늘 동작하는 상태로 두고, 일은 새 브랜치에서 한다.
  • 원격 저장소 — push로 올리고, fetch/pull로 받는다. 올리기 전에 먼저 받는다.
  • 충돌 — 같은 줄을 다르게 고치면 Git이 사람에게 고르게 한다. 표시를 지우고 고른 뒤 다시 커밋한다.
  • Pull Request와 GitHub Flow — 브랜치 → 커밋 → push → PR → 리뷰 → merge. 팀 프로젝트는 이 순서로만 main에 합친다.
  • GitHub Organizations — 팀 저장소를 조직에 모아 권한과 main 보호 규칙을 한곳에서 관리한다.
  • 안전하게 되돌리기 — 비밀 정보는 .gitignore로 처음부터 막고, 올린 커밋은 revert로 취소한다.
  • 태그로 따라잡기 — 놓친 단계는 강사 저장소의 태그로 이동해 비교하며 따라간다.

한눈에 보는 핵심

커밋 = 사진 한 장, 브랜치 = 움직이는 이름표, 태그 = 고정된 이름표

올리기 전에 먼저 받는다: pull → 작업 → push

main에는 PR로만 합친다

자주 쓰는 명령 한 장 요약

하고 싶은 일 명령
처음 설정 git config --global user.name "이름"
저장소 만들기 / 받기 git init / git clone 주소
상태 보기 git status, git diff, git log --oneline --graph
사진 찍기 git add 파일, git commit -m "메시지"
브랜치 git branch, git switch -c 새이름, git switch 이름, git merge 이름
원격 git remote add origin 주소, git push -u origin 브랜치, git fetch, git pull
되돌리기 git restore 파일, git restore --staged 파일, git revert 커밋
태그 git tag, git switch --detach 태그

체크리스트

말로 설명할 수 있으면 통과입니다. 오늘 퀴즈는 이 목록에서 나옵니다.

  • [ ] Git과 GitHub의 차이를 한 문장으로 말할 수 있다.
  • [ ] 세 영역(작업 폴더·스테이징·저장소)과 add, commit이 하는 일을 말할 수 있다.
  • [ ] git status 결과를 보고 파일이 어느 영역에 있는지 말할 수 있다.
  • [ ] 브랜치가 "이름표"라는 뜻을 그림으로 그릴 수 있다.
  • [ ] push가 거절당했을 때 무엇을 먼저 해야 하는지 말할 수 있다.
  • [ ] 충돌 표시(<<<<<<<, =======, >>>>>>>)를 지우고 해결 커밋을 만들 수 있다.
  • [ ] GitHub Flow 6단계를 순서대로 말할 수 있다.
  • [ ] 우리 팀 저장소의 main에 직접 push할 수 없는 이유를 말할 수 있다.
  • [ ] 비밀 키를 올렸을 때 지우기만으로 끝나지 않는 이유를 말할 수 있다.
  • [ ] revert와 reset --hard의 차이를 말할 수 있다.
  • [ ] 강사 코드 태그로 이동했다가 main으로 돌아올 수 있다.
