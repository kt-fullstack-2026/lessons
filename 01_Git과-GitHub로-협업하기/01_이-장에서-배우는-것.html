1장. Git과 GitHub로 협업하기

Git과 GitHub는 왜 첫 장인가

준비시간30분개념 지도전체 흐름

한 줄 요약

이 장에서는 코드의 변경 기록을 남기는 도구(Git)와 그 기록을 팀이 함께 쓰는 서비스(GitHub)를 배웁니다. 이 과정의 모든 실습, 팀 프로젝트, 코드 리뷰가 이 두 가지 위에서 돌아가므로 가장 먼저 배웁니다.

이 장의 실습은 모두 Git Bash에서 명령어로 합니다. IntelliJ나 VS Code의 Git 버튼은 써도 되지만, 명령어로 먼저 익혀야 버튼이 무슨 일을 하는지 알 수 있습니다.

1. Git과 GitHub는 다릅니다

Git이란? 파일의 변경 사항을 추적하고, 여러 사람이 같은 파일로 하는 작업을 조율하는 분산 버전 관리 시스템입니다.

GitHub란? Git 저장소를 인터넷에 올려 두고, 팀이 함께 관리하고 협업할 수 있게 해 주는 웹 서비스입니다.

구분 Git GitHub
정체 내 PC에 설치하는 프로그램 인터넷에 있는 웹 서비스
하는 일 파일의 변경 기록(커밋)을 남긴다 그 기록을 올려 두고 팀이 함께 본다
인터넷 없어도 동작한다 있어야 한다

Pull Request, Issue, Actions는 Git이 아니라 GitHub의 기능입니다. 헷갈리면 "내 PC에서 하는 일인가, 웹 화면에서 하는 일인가?"를 물어보세요.

2. 개념 지도 — 파일이 지나가는 길

파일 수정 → add(고르기) → commit(사진 찍기) → push(올리기)
팀원이 올린 사진은 pull로 받아 옵니다.

3. 이 장에서 손으로 익힐 것과 나중에 찾아볼 것

손으로 익힐 것 (핵심 개념 7개): 커밋, 세 영역, 브랜치, 로컬과 원격, 충돌, Pull Request, .gitignore와 비밀 정보

필요할 때 찾아볼 것: rebase, cherry-pick, stash, Git 내부 구조. 처음에는 몰라도 팀 프로젝트를 할 수 있습니다. 필요해지면 공식 문서(git-scm.com/docs)에서 찾아봅니다.

명령은 무슨 일을 하는지 알고 칩니다. Git 명령은 잘못 치면 기록이 사라질 수 있습니다. 모르는 명령을 복사해 붙여 넣기 전에 git status로 지금 상태부터 확인합니다.
