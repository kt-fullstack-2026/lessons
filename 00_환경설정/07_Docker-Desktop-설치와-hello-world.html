0장. 환경설정 — 과정 전체 개발 도구 설치

Docker Desktop(WSL 2) 설치와 docker run hello-world 확인

준비시간40분개념 지도07 Docker Desktop

한 줄 요약

14장부터 서버 · DB · Redis · Kafka를 설치하지 않고 컨테이너로 띄웁니다. 컨테이너는 Linux의 기능으로 돌기 때문에, Windows에서는 WSL 2라는 "Windows 안의 작은 Linux" 위에서 Docker가 돕니다. Docker Desktop은 이것을 한 번에 준비해 주는 프로그램입니다. 설치할 때 WSL 2 방식을 고르고, 처음 켤 때 약관에 동의한 뒤, 터미널에서 docker run hello-world로 첫 컨테이너를 돌려 봅니다.

설치 시점: 14장 직전. CPU의 가상화 기능이 꺼져 있는 노트북은 드물지만, 4절에서 가상화 오류가 나면 4절의 표대로 BIOS(UEFI)에서 켭니다.

1. 구조 먼저

요구 사항 (Docker 문서) 비고
Windows 11 64비트, 23H2(빌드 22631) 이상 최근 2~3년 안에 산 노트북은 대부분 만족한다. 설치가 막히면 설정 → Windows 업데이트로 먼저 최신 버전으로 올린다
하드웨어 가상화가 켜져 있음, 메모리 8GB 이상 대부분 켜져 있다. 4절에서 가상화 오류가 나면 4절의 표대로 BIOS(UEFI)에서 켠다
WSL 2.1.5 이상 아래 2절

출처: Docker 문서 — Install Docker Desktop on Windows

2. WSL 확인 — 필요할 때만 업데이트

Windows 11에는 WSL이 들어 있지만 낡은 버전일 수 있습니다. 확인만 해 봅니다.

  1. 시작 버튼을 오른쪽 클릭 → 터미널(관리자)를 고릅니다. "디바이스를 변경하도록 허용"에 예.
  2. 아래를 칩니다.
wsl --version
보이는 것 할 일
WSL 버전: 2.x.x 같은 줄이 여러 개 (2.1.5 이상) 그대로 3절로
버전 정보 대신 도움말이 길게 나오거나, 2.1.5보다 낮다 아래 명령으로 업데이트한다 
wsl --update

WSL이 아예 없다는 안내가 나오면 wsl --install을 칩니다. 다시 시작하라고 하면 컴퓨터를 다시 시작합니다. 이 관리자 터미널은 이 절에서만 쓰고 닫습니다.

출처: Docker 문서 — WSL: Verification and setup, Microsoft 문서 — Install WSL

3. Docker Desktop 설치

  1. docker.com에서 Download for Windows – AMD64를 눌러 Docker Desktop Installer.exe를 받습니다.
  2. 받은 파일을 더블클릭합니다. 설치 방식(내 계정만 · 모든 사용자)을 물으면 기본값(내 계정만, per-user)을 고릅니다. 관리자 권한 없이 설치 · 업데이트됩니다.
  3. Configuration 화면에서 Use WSL 2 instead of Hyper-V를 고릅니다. 버전에 따라 WSL 2가 목록의 한 항목으로 나오기도 하는데, 그때도 WSL 2를 고릅니다. 이것이 이 과정의 방식입니다.
  4. 안내대로 진행하고, 끝나면 Close를 누릅니다. 다시 시작하라는 안내가 나오면 따릅니다.

Docker Desktop은 설치 뒤 저절로 켜지지 않습니다. 다음 4절처럼 직접 켭니다. 그리고 처음 켤 때 서비스 약관(Docker Subscription Service Agreement)에 Accept를 눌러야 엔진이 돕니다. Docker Desktop은 개인 · 교육 · 작은 회사(직원 250명 미만이고 연 매출 1천만 달러 미만)에서는 무료입니다. 로그인(Sign in)은 하지 않아도 이 과정의 실습이 됩니다. 15장에서 Docker Hub 계정을 만들 때 다시 봅니다.

출처: Docker 문서 — Start Docker Desktop, 라이선스 요약

4. 켜고 docker run hello-world

  1. 시작 메뉴에서 Docker Desktop을 엽니다. 약관 창이 나오면 Accept를 누릅니다. 설문 · 로그인 화면은 Skip으로 넘어갑니다.
  2. 창 왼쪽 아래가 Engine running(초록)이 되고, 작업 표시줄 오른쪽 아래에 고래 아이콘이 보이면 켜진 것입니다. 처음에는 1~2분 걸립니다.
  3. VS Code를 다시 켜고 새 터미널(Ctrl + `)에서 칩니다.
docker --version
docker compose version

Docker version 29.8.2, build 7fc2dff
Docker Compose version v5.6.0

숫자는 받은 때에 따라 다릅니다. 두 줄 모두 버전이 나오면 됩니다. 이제 첫 컨테이너를 돌립니다.

docker run hello-world

Unable to find image 'hello-world:latest' locally
latest: Pulling from library/hello-world
…
Status: Downloaded newer image for hello-world:latest

Hello from Docker!
This message shows that your installation appears to be working correctly.
…

Hello from Docker!가 보이면 성공입니다. 처음 두 줄은 "내 컴퓨터에 hello-world 이미지가 없어서 Docker Hub에서 받는다"는 뜻이고, 두 번째부터는 바로 Hello from Docker!가 나옵니다. 이미지 · 컨테이너가 무엇인지는 14장에서 배웁니다.

보이는 것 원인 할 일
error during connect · The system cannot find the file specified · docker daemon is not running Docker Desktop이 꺼져 있거나 아직 켜지는 중 Docker Desktop을 켜고 Engine running이 될 때까지 기다린다
Docker Desktop이 "Virtualization support not detected" 같은 오류로 멈춘다 가상화가 꺼져 있다 노트북을 다시 켜면서 제조사가 안내하는 키(삼성 · LG는 보통 F2)로 BIOS(UEFI)에 들어가, Virtualization(Intel VT-x 또는 AMD SVM) 항목을 Enabled로 바꾸고 저장한다. 정확한 키와 메뉴 이름은 제조사 지원 페이지에서 "가상화 켜기"로 찾는다. 다른 설정은 바꾸지 않는다
WSL 관련 오류로 엔진이 안 켜진다 WSL이 낡았다 2절 wsl --update 뒤 컴퓨터를 다시 시작한다
'docker' 용어가 … 인식되지 않습니다 터미널이 설치 전 것 VS Code를 다시 켠다

쓰지 않을 때는 Docker Desktop을 끕니다. Docker Desktop은 켜 두기만 해도 WSL 2 가상 머신이 메모리를 꽤 씁니다. 13장까지는 쓰지 않으니, 확인이 끝나면 작업 표시줄의 고래 아이콘을 오른쪽 클릭 → Quit Docker Desktop으로 끕니다. Windows를 켤 때 저절로 켜지지 않게 하려면 Docker Desktop Settings → General의 Start Docker Desktop when you sign in to your computer를 끕니다.

핵심 정리

  • Docker Desktop은 WSL 2(Windows 안의 작은 Linux) 위에서 Docker 엔진을 돌린다. 가상화가 켜져 있어야 하고, 꺼져 있으면 BIOS(UEFI)에서 켠다.
  • 관리자 터미널에서 wsl --version을 보고, 낡았으면 wsl --update.
  • 설치는 기본값(내 계정만), Configuration에서 WSL 2를 고른다. 처음 켤 때 약관에 Accept.
  • Engine running을 본 뒤 새 터미널에서 docker --version · docker compose version · docker run hello-world → Hello from Docker!
  • 안 쓸 때는 Quit Docker Desktop으로 꺼서 메모리를 아낀다.
