0장에서 한 것

  • 설치 전 확인(03절) — 파일 확장명 · 숨긴 항목 보이기, 한글 · 빈칸 없는 D:\workspace.
  • VS Code(04절) — User 설치, Prettier · ESLint · Live Share 확장, 저장할 때 정리, Live Share 세션 참여 3단계(온라인 수업 때).
  • Node.js 24 LTS(05절) — .msi 기본값 설치, 새 터미널에서 node -v · npm -v, 실행 정책 오류 풀기.
  • JDK 21 · IntelliJ IDEA(06절) — Temurin 21 설치 중 Set JAVA_HOME 켜기, 하나로 합쳐진 IntelliJ, JDK 목록에 21 확인.

  • PostgreSQL 17 · pgAdmin 4(08절) — 비밀번호를 정해 적어 두기, 포트 5432, 서비스 실행 중, pgAdmin 접속.

한눈에 보는 핵심

도구는 쓰기 직전에 하나씩 설치한다

설치가 끝나면 터미널을 새로 연다 — 열려 있던 터미널은 바뀐 PATH를 모른다

큰 번호만 맞춘다 — Node 24, JDK 21, PostgreSQL 17

1. 버전 명령 한 번에

설치를 하나 끝낼 때마다, 그리고 수업 중 "명령을 못 찾는다"는 오류가 날 때마다 아래를 칩니다. VS Code를 다시 켜고 새 터미널(Ctrl + `)에 한 줄로 붙여 넣습니다. PowerShell에서 ;는 "앞 명령이 끝나면 다음 명령"이라는 뜻입니다.

git --version; node -v; npm -v; java -version; docker --version; docker compose version

모든 도구를 설치한 뒤라면 아래와 같은 모양이 나옵니다. 숫자의 뒷자리는 받은 때에 따라 다릅니다.

11.19.1

아직 설치할 때가 안 된 도구(예: 2장 전이면 java, docker)는 "인식되지 않습니다"가 나오는 것이 정상입니다. 그 줄은 그 장 직전에 다시 봅니다.

PostgreSQL은 명령 대신 화면으로 확인합니다. 서비스 앱에서 postgresql-x64-17이 실행 중이고, pgAdmin 4에서 Servers → PostgreSQL 17에 접속되면 됩니다(08절 3 · 4).

문의가 있을 때는 "안 돼요" 대신 세 가지를 보냅니다. ① 친 명령, ② 나온 글자 전체(복사해서 붙여 넣기), ③ 1절 버전 명령의 결과. 이 셋이 있으면 원인의 대부분을 바로 찾습니다.

3. 따로 설치하지 않는 것

교안에서 이름은 자주 나오지만, 이 장에서 설치 프로그램으로 설치하지 않는 것들입니다. 각 장에서 명령이나 파일로 저절로 받아집니다.

핵심 정리

  • 새 터미널에서 git --version; node -v; npm -v; java -version; docker --version; docker compose version을 한 줄로 친다.
  • 큰 번호를 본다: Node v24., Java "21. · Temurin. PostgreSQL은 서비스 앱과 pgAdmin 접속으로 본다.
  • "인식되지 않습니다"는 대부분 터미널을 새로 열지 않아서다. 아직 설치할 때가 안 된 도구라면 정상이다.
  • Gradle · Spring · npm 라이브러리 · 컨테이너 이미지는 따로 설치하지 않는다.
  • 막히면 명령 · 나온 글자 전체 · 버전 명령 결과를 함께 보낸다.

실습문제와 힌트

문제 1. 설치 확인 화면 제출하기

2장 첫 수업 전에 VS Code 터미널에서 1절의 버전 명령을 치고, VS Code 창 전체가 보이게 화면을 캡처해 제출합니다. 캡처에는 아래 셋이 보여야 합니다.

  • 터미널 맨 앞의 경로 PS D:\workspace> (D 드라이브가 없으면 PS C:\workspace>)
  • node -v의 v24.
  • 왼쪽 Extensions의 Installed 목록에 Prettier · ESLint · Live Share

10장 직전과 14장 직전에도 같은 명령을 다시 쳐서, java · docker 줄까지 나온 화면을 한 장씩 더 제출합니다.

힌트 보기
  • 방향: 명령은 1절의 한 줄을 그대로 복사해 붙여 넣습니다. 아직 설치하지 않은 도구의 오류 줄은 있어도 됩니다.
  • 볼 곳: 경로가 D:\workspace가 아니면 04절 4처럼 폴더를 오른쪽 클릭 → Code(으)로 열기로 다시 엽니다.
  • 함정: 설치하고 VS Code를 다시 켜지 않으면 node를 못 찾습니다. 화면 캡처는 Windows 키 + Shift + S로 합니다.
  • 확인: 캡처를 열어 경로 · v24. · 확장 세 개가 모두 읽히는지 봅니다.

문제 2. pgAdmin 접속과 비밀번호 확인하기

9장 직전에, pgAdmin 4에서 Servers → PostgreSQL 17 → Databases → postgres까지 펼친 화면을 캡처해 제출합니다. 그리고 08절에서 정한 비밀번호를 어디에 적어 두었는지를 한 줄로 적습니다(비밀번호 자체는 적지 않습니다).

힌트 보기
  • 방향: 08절 4의 순서를 그대로 따라갑니다.
  • 볼 곳: 접속이 안 되면 먼저 서비스 앱의 postgresql-x64-17 상태를 봅니다.
  • 함정: 비밀번호 창에서 한/영 키가 한글로 되어 있으면 맞는 비밀번호도 틀린 것이 됩니다.
  • 확인: Databases 아래에 postgres가 보이고, Save Password를 체크했다면 pgAdmin을 다시 열어도 비밀번호를 묻지 않습니다.
