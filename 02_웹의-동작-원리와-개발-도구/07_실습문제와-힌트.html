2장. 웹의 동작 원리와 개발 도구

실습문제와 힌트 — 기본 · 필수 · 도전

1단계 핵심시간50분개념 지도전체 흐름

먼저 스스로 풀어 봅니다. 막히면 힌트를 하나씩 펼쳐 봅니다. 해답은 수업 시간에 함께 확인합니다. 입문자는 기본 → 필수, 이수자는 필수 → 도전을 목표로 합니다.

자기소개 페이지를 만들어 브라우저로 열고, 고친 내용을 확인한다.

URL을 부분별로 나누고, 상황별 상태 코드를 맞힌다.

HTTP 응답 메시지를 읽고, 화면이 나오기까지의 흐름을 설명한다.

문제 1 (기본) — 자기소개 페이지 띄우기

  1. VS Code로 D:\workspace\web-basic 폴더를 열고 about.html을 만든다.
  2. 제목(<h1>)에 이름, 문단(<p>) 두 개에 관심 분야와 목표를 쓴다.
  3. 브라우저로 연 뒤, 문단을 하나 더 추가하고 저장 → 새로고침해서 바뀐 것을 확인한다.
힌트 보기
  1. 5절 따라하기 2의 첫 HTML 파일과 같은 기본 틀로 시작합니다. VS Code에서 !를 치고 Enter를 누르면 기본 틀이 한 번에 나옵니다.
  2. 이름은 <body> 안의 <h1>에, 관심 분야와 목표는 <p> 두 개에 나눠 씁니다. <html lang="ko">와 <meta charset="UTF-8">가 있는지 봅니다.
  3. 함정: 문단을 추가한 뒤 Ctrl + S로 저장하지 않으면 새로고침해도 바뀌지 않습니다. 브라우저는 저장된 파일을 읽기 때문입니다.
  4. 확인하는 법: Windows 탐색기에서 about.html을 더블클릭합니다. 주소창에 file:///D:/workspace/web-basic/about.html이 보이고, 저장 → 새로고침 후 새 문단이 나타나면 성공입니다.

문제 2 (필수) — URL 나누기와 상태 코드 맞히기

(1) 아래 URL을 스킴 · 도메인 · 포트 · 경로 · 쿼리로 나누세요.

http://localhost:8080/api/posts?page=1&size=10

(2) 각 상황에서 받게 될 상태 코드를 고르세요. (200, 201, 401, 404, 500)

상황
① 게시판 글 목록을 정상적으로 조회했다
② 주소의 posts를 post로 잘못 썼다
③ 새 글 쓰기(POST)에 성공했다
④ 로그인하지 않고 내 정보 페이지를 요청했다
⑤ 서버 코드에서 처리하지 못한 오류가 났다
힌트 보기
  1. (1)은 3절 2의 "URL 읽는 법"을 옆에 두고 앞에서부터 기호로 끊어 봅니다. ://, :, 첫 /, ?가 경계입니다.
  2. (2)는 4절 4의 상태 코드 표를 봅니다. 먼저 "잘 됐다(2xx)", "요청 쪽 실수(4xx)", "서버 쪽 문제(5xx)" 중 어디인지 고른 뒤, 그 안에서 숫자를 고릅니다.
  3. 함정: 포트가 주소에 적혀 있는 이유를 생각합니다(기본 포트가 아니면 생략할 수 없습니다). 쿼리는 &로 이어 붙은 값이 몇 개인지 셉니다. ③은 "조회 성공"과 "새로 만들기 성공"이 서로 다른 숫자입니다.
  4. 확인하는 법: (1)은 다섯 칸이 모두 채워지고 남는 글자가 없어야 합니다. (2)는 다섯 상황에 다섯 숫자를 한 번씩 썼는지 봅니다.

문제 3 (도전) — 응답 메시지 읽기

아래는 브라우저가 어떤 주소를 요청하고 받은 응답입니다.

HTTP/1.1 404 Not Found
Content-Type: text/html; charset=utf-8

<!doctype html>
<html>
<head><title>페이지를 찾을 수 없습니다</title></head>
<body><h1>요청한 페이지가 없습니다</h1></body>
</html>
  1. 상태 코드, Content-Type, 본문을 각각 찾는다.
  2. 이 응답은 요청 쪽 문제인지 서버 쪽 문제인지 말하고, 이유를 쓴다.
  3. 이 응답을 받은 브라우저 화면에는 무엇이 보일지 말한다.
  4. 주소창에 http://example.com을 치고 화면이 나오기까지를 1절 그림의 ①~④로 설명한다.
힌트 보기
  1. 4절 2의 "실제 응답 읽어 보기"처럼 응답을 첫 줄 · 헤더 · 빈 줄 · 본문으로 나눠서 봅니다.
  2. 상태 코드의 앞자리 숫자로 누구 쪽 문제인지 정합니다(4절 4). 서버가 "없다"는 답을 보냈다는 사실도 함께 생각합니다.
  3. 함정: 404 응답에도 본문이 있을 수 있습니다. 본문이 HTML이면 브라우저는 그것을 그대로 그립니다. 탭 제목은 <title>, 화면의 큰 글자는 <h1>에서 나옵니다.
  4. 확인하는 법: 4번은 3절 1의 그림 순서(DNS → 요청 → 응답 → 화면)대로 네 줄을 쓰고, 줄마다 이번 주소(example.com, 포트, GET /, 상태 코드)를 넣었는지 확인합니다.
