2장. 웹의 동작 원리와 개발 도구

용어 정리

1단계 핵심시간40분개념 지도전체 흐름

1. 클라이언트와 서버

용어 뜻 예
클라이언트 (client) 서비스를 요청하는 쪽 브라우저, 스마트폰 앱
서버 (server) 요청을 받아 처리하고 응답하는 쪽 네이버 서버, 나중에 만들 Spring 서버
브라우저 (browser) 웹 문서를 요청하고, 받은 내용을 화면으로 그리는 프로그램 Chrome, Edge, Whale, Safari

client는 "손님", serve는 "음식을 내다, 시중들다"라는 뜻입니다. 같은 컴퓨터가 상황에 따라 클라이언트도 되고 서버도 됩니다. 9장부터는 내 PC 하나가 둘 다 합니다.

2. IP 주소와 DNS

용어 뜻 예
IP 주소 인터넷에 연결된 기기의 숫자 주소 203.0.113.10 (예시용 주소)
도메인 (domain) 사람이 기억하기 쉽게 붙인 이름 주소 naver.com, example.com
DNS (Domain Name System) 도메인을 IP 주소로 바꿔 주는 시스템. 인터넷의 주소록 example.com → IP 주소
localhost "이 컴퓨터 자신"을 가리키는 이름. IP로는 127.0.0.1 9장부터 만드는 내 서버

IP 주소는 바뀔 수 있습니다. 그래서 사람은 도메인을 쓰고, 컴퓨터는 접속할 때마다 DNS로 IP를 찾습니다. 위 표의 IP는 예시입니다.

3. URL과 포트

용어 뜻 자세히
URL (Uniform Resource Locator) 인터넷에 있는 자원(문서, 이미지, 데이터)의 전체 주소 3절
포트 (port) 한 서버 안에서 어느 프로그램에게 갈지 정하는 번호. 건물 주소가 IP라면 포트는 호수입니다 3절
경로 (path) 서버 안에서 어떤 자원인지 가리키는 부분. /products 3절

자주 보는 포트 번호입니다.

포트 쓰는 곳
80 HTTP 기본
443 HTTPS 기본
5173 Vite 개발 서버 기본 (8장 React)
8080 Spring Boot 기본 (10장)

4. HTTP에 관한 말

용어 뜻 자세히
HTTP (HyperText Transfer Protocol) 브라우저와 서버가 요청과 응답을 주고받는 약속(규칙) 4절
HTTPS HTTP에 암호화를 더한 것. S는 Secure입니다 4절
프로토콜 (protocol) 컴퓨터끼리 통신할 때 지키는 약속 4절
요청 (request) 클라이언트가 서버에 보내는 메시지 4절
응답 (response) 서버가 클라이언트에 돌려주는 메시지 4절
메서드 (method) 요청이 무엇을 하려는지. GET(가져오기), POST(새로 만들기) 등 4절
상태 코드 (status code) 응답의 결과를 알리는 세 자리 숫자. 200(성공), 404(없음), 500(서버 오류) 4절
헤더 (header) 요청 · 응답에 붙는 부가 정보. 내용 종류, 길이 등 4절
본문 (body) 실제로 보내는 내용. HTML, JSON 등 4절

HyperText는 링크로 다른 문서와 연결된 글이라는 뜻입니다. 그래서 웹 문서를 만드는 언어 이름이 HTML(HyperText Markup Language)입니다.

5. 도구에 관한 말

용어 뜻 자세히
에디터 (editor) 코드를 쓰는 프로그램. 이 과정은 웹 쪽은 VS Code를 씁니다 5절
확장 (extension) VS Code에 기능을 더하는 추가 프로그램 5절

핵심 정리

  • 클라이언트는 요청하고, 서버는 응답한다.
  • 도메인은 DNS를 통해 IP 주소로 바뀐다. localhost는 내 PC 자신이다.
  • HTTP는 요청과 응답의 약속이고, 결과는 상태 코드로 알린다.
